## 1. Что берём из предложения как есть

1. **Модель решает, код исполняет.** Монтажный план — файл (`edit_plan.json`),
   рендерер детерминирован. Никаких «Claude → команда ffmpeg».
2. **Hard cut по умолчанию.** Переход — исключение, которое надо обосновать.
3. **Музыка — отдельная дорожка с даккингом под голос.** Самый большой прирост
   «профессиональности» на единицу работы.
4. **Субтитры пословные, стиль выбирается, а не один на все ролики.**
5. **Готовый файл меряется** (уже наш принцип): к `frozen_sec` и `av_drift_sec`
   добавляются громкость, пик, чёрные и застывшие кадры, покрытие речи субтитрами.
6. **Remotion остаётся** для программного движения и позже — для кинетических
   субтитров, если libass окажется недостаточно.
7. **Чужие редакторы (Phantom, dawn-cut, OpenReelio, DaVinci как ядро) не берём.**

## 2. От чего отказываюсь и почему

1. **Whisper / WhisperX для таймингов слов.** Тайминги уже есть из самого
   синтезатора — точнее любого распознавания, бесплатно, без GPU. ASR
   переоткрывал бы с ошибками то, что мы знаем точно. Whisper нужен только
   `clips_from_long` (чужой звук) — там он и запланирован (RunPod). Правило:
   тайминги слов — обязанность `TtsProvider` (уже так: `meta["srt"]`); провайдер,
   который их не отдаёт, получает ASR как *свою* внутреннюю деталь, не как стадию.
2. **Второй «глобальный режиссёр монтажа»** (Hook/Setup/Conflict/Payoff по
   готовым клипам). Структура решена в `story.json` и `retention.json`, границы
   сцен — планнером. Вторая модель, судящая темп по готовым клипам, — второй
   источник правды, который к тому же ничего не может изменить дёшево: кадры уже
   оплачены. Стадия монтажа **читает** `retention.json` как карту (где смена, где
   мёртвая зона, где кульминация) и решает только то, что решается монтажом:
   переходы, музыкальные ступени, акценты в субтитрах, окно клипа.
3. **Генерация или подбор новых визуалов внутри монтажа** («кадр слишком длинный —
   подберём другой фрагмент/сгенерируем B-roll»). Это деньги после ворот, где
   человек одобрил конкретный набор кадров. Правильное место — планнер (он уже
   режет длинные биты) либо находка `warn` на воротах: «сцене s07 не хватает
   визуала» → человек добавляет сцену → конвейер идемпотентно доделывает.
4. **Анализ движения ради «выбрать интересный участок клипа» как первый шаг.**
   Длина клипа выбирается по измеренной речи *до* генерации, потери — максимум
   4 с на Hailuo и 0 на remotion. Клип i2v начинается с одобренного кадра —
   отрезав голову, мы выбросим кадр, который человек утверждал, и начнём с
   середины движения. Пример из предложения («0–3 с персонаж стоит, 6–8 с
   кульминация») — дефект `motion_prompt` («action begins immediately») и
   проверки клипа, а не задача монтажёра. Что *стоит* измерять: энергию движения
   по полусекундам, чтобы (а) ловить мёртвые клипы как брак генерации и (б)
   ставить срез хвоста в тихий момент. Это инкремент 4, не 1.
5. **Parallax, camera shake, speed ramps, punch-in поверх i2v, reframing.**
   Parallax требует слоёв (фон/персонаж/передний план), которых у нас нет —
   отдельная подсистема сегментации. Замедление 24-fps генеративного видео без
   интерполяции дёргается. Punch-in поверх клипа, где камера уже едет, — двойное
   движение, тошнит. Для remotion-сцен «punch-in» — это параметры того же
   рендера (`zoomFrom/zoomTo`), а не постэффект. Reframing 16:9 → 9:16 для
   генеративного контента неверен по постановке: кадр генерируется сразу в
   нужном формате; reframing — забота нарезок.
6. **Цикл «рендер → QA → Claude правит план → рендер» как главный механизм
   качества.** Рендер десятиминутного эпизода — минуты; три круга — полчаса
   ожидания ради вердикта vision-модели, который плывёт между прогонами. У нас
   уже есть рабочая схема: python меряет → `block` возвращается модели **до**
   дорогого шага (планнер + variation), `warn` — человеку на воротах. Так же и
   здесь: линт плана — до рендера, с одной повторной попыткой; измерения
   готового файла — в отчёт и в сообщение ворот. Измеренный `block` после
   рендера (громкость не в норме, дрейф) — это баг рендерера, чинится кодом, а не
   перепланированием. Vision-оценка финала — совет на воротах, не водитель цикла.
7. **Пакет `videoforge/editing/` из 12 модулей сразу.** Месяц каркаса до первого
   видимого улучшения. И слоистость: стадия монтажа — это стадия
   (`stages/edit.py`), её схема — ядро (`core/editplan.py`), рендерер — `core/ffmpeg`
   + провайдер remotion. Растёт по возможности за возможностью, каждая
   заканчивается новым `final.mp4`, который можно посмотреть.
8. **SFX в первом заходе.** Нужна библиотека с правами, теги, вкус; лишний
   whoosh хуже его отсутствия. Музыка с даккингом даёт большую часть эффекта.
   SFX — после двух эпизодов с музыкой, как ресурс с тегами и квотой.
9. **DaVinci как «ручной фолбэк» в конвейере.** Интегрировать нечего. Если
   захочется править руками — экспорт плана в OTIO/FCPXML, V3+.
10. **Перекрывающиеся переходы (crossfade/xfade) в первой версии.** Перекрытие
    съедает время у обеих сцен и требует такого же кроссфейда звука — общая
    длительность перестаёт быть суммой измеренных сцен, ломается власть озвучки
    над временем и `test_final_is_measured_not_assumed`. В v1 переходы только
    внутри коробки сцены: cut, dip-to-black (fade out + fade in), fade.

## 3. Архитектура

### 3.1 Две стадии, один контракт, власть над временем

```
… → video → edit (LLM, $0) → 05_edit/edit_plan.json → assemble (рендер) → ворота → publish
```

- **`edit`** пишет план. Свежесть — как у режиссёра: файл есть, новее своих
  входов (`storyboard.json`, `retention.json`, ресурсы стиля/музыки) и сделан
  текущей моделью → пропуск. Поправленный руками план новее → побеждает, но
  проходит тот же линт (блок → `failed` с текстом, без повторного вызова модели).
- **`assemble`** рендерит план. **Плана нет → план по умолчанию** (hard cut везде,
  субтитры по `project.video.captions`, музыка по `project.video.music`,
  fade-in/out). Это значит, инкремент 1 даёт субтитры и музыку без единого
  вызова LLM, а стадия `edit` добавляется поверх, когда рендерер уже измерен.
- **Власть над временем не передаётся.** Порядок сцен и `duration_sec` — из
  раскадровки, план их не содержит. План решает, что *внутри* коробки сцены и на
  её границах. Это единственный способ сохранить «ритм задаёт голос» и все
  замеры финала.

### 3.2 EditPlan (`core/editplan.py`, набросок)

```python
class MotionOverride(BaseModel):  # только для сцен с provenance still-based (remotion)
    motion: Literal[
        "push_in", "pull_out", "pan_left", "pan_right", "tilt_up", "tilt_down", "static"
    ]
    strength: float = 0.10
    focus_x: float = 0.5  # к чему едет камера, доли кадра
    focus_y: float = 0.5


class SceneEdit(BaseModel):
    scene_id: str
    source_in_sec: float = (
        0.0  # с какой секунды клипа взять окно duration_sec (i2v; ≤ len − duration)
    )
    transition_in: Literal["cut", "dip_black", "fade"] = "cut"
    fade_out_sec: float = 0.0
    motion: MotionOverride | None = None
    emphasis: list[str] = []  # слова-акценты в субтитрах, ≤ 2 на сцену
    captions: bool = True
    music_gain_db: float | None = None  # ступень громкости музыки начиная с этой сцены
    sfx: list[SfxCue] = []  # инкремент 6
    why: str = ""  # обоснование отклонения от умолчания — читает человек


class MusicPlan(BaseModel):
    track: str  # id ресурса resources/music/<id>.yaml
    gain_db: float = -18.0
    duck_db: float = 10.0  # насколько падает под голос
    fade_in_sec: float = 1.0
    fade_out_sec: float = 2.0


class EditPlan(Artifact):  # llm, generated_at — как у артефактов сценариста
    caption_style: str  # id ресурса resources/caption_styles/<id>.yaml
    music: MusicPlan | None = None
    fade_in_sec: float = 0.3
    fade_out_sec: float = 0.8
    scenes: list[SceneEdit] = []  # только сцены с отклонениями; отсутствие = умолчание
```

Компактность намеренная: время `claude -p` определяется длиной ответа
(6 с + символы/90), план на 100 сцен «только отклонения» — минута-две, полный —
семь.

### 3.3 Рендерер

Остаётся ffmpeg, растёт `core/ffmpeg.py` плюс новый `core/captions.py`:

1. `mux_scene` получает `source_in_sec`, fade-in/out внутри коробки; для
   remotion-сцен с `MotionOverride` клип перерендеривается провайдером (это
   $0 и тот же `VideoProvider.animate` с расширенным промптом/props).
2. `concat` — как сейчас, с перекодированием.
3. `core/captions.py`: `.srt` слов → группы-фразы (порт `build_groups` из
   `docs/reference/arcads-prompting/caption-video-guide.md`: ≤ 22 символов, ≤ 5
   слов, разрыв на паузе > 0.55 с и на знаках) → **ASS** со стилем из ресурса и
   караоке-тегами `\k` для подсветки текущего слова, `\fad` для появления.
   Смещение сцены в финале — сумма **измеренных** `measured_sec["clip"]`
   предыдущих сцен, не `duration_sec`. Шрифт с кириллицей лежит в репозитории
   (`videoforge/assets/fonts/`, лицензия OFL), передаётся `fontsdir=`.
4. Музыка: `amix` голоса и трека, `sidechaincompress` голосом как ключом
   (ratio/threshold/release из ресурса стиля), ступени `music_gain_db` — `volume`
   с выражением по времени; `afade` на входе/выходе.
5. `loudnorm` в два прохода до цели площадки (−14 LUFS, пик ≤ −1 dBTP), затем
   `ebur128` — измерить и записать.
6. Измерения в `FinalOutput`: `loudness_lufs`, `true_peak_dbtp`, `black_sec`
   (`blackdetect`), `frozen_detected_sec` (`freezedetect` — независимо от нашего
   расчёта `frozen_sec`: два способа посчитать одно и то же ловят баг друг в
   друге), `caption_coverage` (доля секунд речи, накрытых субтитрами),
   `music_track`, `captions` (путь к .ass).

Remotion для субтитров — **только если** libass окажется недостаточно по глазам
после двух эпизодов (пружинящие «pop»-анимации ASS даёт хуже). Тогда — отдельная
композиция `Captions` над магентой + `chromakey` (рецепт из того же гайда), а не
полноэпизодная композиция с видео внутри Chrome: она медленная.

### 3.4 Ресурсы

- `resources/caption_styles/<id>.yaml`: шрифт, размер, позиция (нижняя треть /
  центр для 9:16 с учётом зоны UI площадки), режим `phrase | word | karaoke`,
  цвета, обводка, `max_words`, `max_chars`, анимация появления. В шаблонах —
  4 пресета: `documentary`, `kinetic_shorts`, `calm`, `tense`.
- `resources/music/<id>.yaml`: файл, **`license` и `source` обязательны**,
  теги настроения/темпа, `loop_ok`, рекомендуемый `gain_db`. Использованный трек
  записывается в манифест (комплаенс из плана версий).
- `resources/sfx/<id>.yaml` — инкремент 6, то же устройство.
- `project.yaml`: `video.caption_style`, `video.music` становятся id ресурсов
  (шаблон с комментариями обновляется вместе с схемой).

### 3.5 Линт плана (`stages/edit_lint.py`, по образцу `variation.py`)

Считает python, до рендера. `block` → текст ошибки → модель отвечает второй
раз (один раз); `warn` → ворота.

- неизвестный `scene_id`, стиль, трек → `block`;
- `MotionOverride` на сцене с генеративным provenance → `block` (двойное движение);
- `source_in_sec + duration_sec > длина клипа` → `block`;
- доля не-cut переходов > 40% → `block`, > 20% → `warn`;
- `emphasis` > 2 слов на сцену или слово не из narration → `block`;
- ступеней громкости музыки > 6 на эпизод → `warn`;
- SFX (позже): > 4/мин → `block`, whoosh не на переходе → `warn`;
- мок LLM для `edit` обязан давать план **разнообразной формы** (не все cut, не
  все одинаковые ступени) — иначе линт на моках ничего не проверяет (урок
  планнера).

### 3.6 Что видит человек на воротах

`core/report.py` получает «монтажный лист»: по сцене — переход, окно клипа,
движение, группы субтитров с акцентами, ступень музыки, `why`; внизу — таблица
измерений финала против порогов. Без этого ворота после сборки — театр: судить
план по JSON человек не будет.

## 4. Порядок работ

Каждый инкремент заканчивается новым `final.mp4` на `sci_mini/ep001` (60 с,
15 сцен, уже с настоящими кадрами) и строкой измерений в отчёте. Оценки — в
сессиях, грубо.

**0. Подготовка (1 сессия).**
- `doctor`: проверка фильтров ffmpeg (`ass`, `sidechaincompress`, `loudnorm`,
  `ebur128`, `blackdetect`, `freezedetect`) и наличия шрифта — сегодня всё есть,
  но другой ffmpeg в PATH может быть собран без libass.
- Стык `continues` в remotion: чейнинг зума (`zoomFrom/zoomTo` по позиции сцены в
  цепочке) — это стадия `video`, не монтаж, но это самый заметный монтажный
  дефект сегодня, и он мешает оценивать всё остальное.
- Эксперимент 0.25 с lead-in перед голосом (`scene_lead_sec` в `VideoConfig`,
  по умолчанию 0): гайд arcads утверждает, что без него стыки «зажаты». Решать
  глазами, не принимать на веру.

**1. Рендерер по умолчанию: субтитры + музыка + нормализация (2 сессии).**

## 5. Что может пойти не так

1. **План перегружен украшениями** — переход на каждой сцене, акцент на каждом
   слове. Это штатное поведение модели, а не случайность. → Линт с квотами и
   hard cut по умолчанию; в промпте — «отклонение требует `why`».
2. **Двойное движение**: наезд поверх клипа, где камера уже едет. → Эффекты
   только на still-based provenance, линт знает провайдера.
3. **Регресс дрейфа и длительностей**: любая операция, меняющая длину дорожек
   (fade, ass, микс), или соблазн `-c copy` в склейке. → Существующие замеры
   остаются обязательными; тест: сцены с субтитрами и музыкой держат
   `measured_sec["clip"] == duration_sec` и `av_drift < 0.1`.
4. **Громкость**: музыка поднимает интегральную громкость, площадка нормализует
   к −14 LUFS, пики клиппят. → `loudnorm` два прохода, `ebur128` в `final`,
   порог в отчёте.
5. **Права на музыку / Content ID**: случайный трек снимает монетизацию или
   блокирует ролик. → `license` и `source` обязательны в ресурсе; трек в
   манифесте; без лицензии стадия падает, не предупреждает.
6. **Шрифты на Windows**: fontconfig в сборке нет; libass без `fontsdir` возьмёт
   что попало, кириллица может выпасть. → Шрифт в репозитории, явный `fontsdir`,
   `doctor` проверяет файл. Пути в фильтре `ass=` экранируются по-своему
   (двоеточия, обратные слэши) — отдавать через `-filter_complex_script`.
7. **Смещение субтитров между сценами**: AAC-кадр ≈ 23 мс, на 100 сценах
   накапливается. → Смещения по измеренным длинам клипов, а не по плану; тест на
   покрытие речи ловит уход.
8. **Формы слов из синтезатора**: edge-tts возвращает слова как произнесены
   («сто», а не «100»; «километров», а не «км»). → Принять как ограничение
   (субтитры показывают произнесённое), зафиксировать в документе стиля; обратный
   маппинг на текст сценария по порядку — хрупко, не делать.
9. **Время рендера**: полноэпизодная композиция Remotion с видео внутри Chrome —
   десятки минут на 10-минутном ролике. → Субтитры через libass в одном проходе
   ffmpeg; Remotion только для клипов сцен (как сейчас) и, если понадобится, для
   субтитров над магентой.
10. **Два источника правды о времени**, если план сможет менять порядок или длину
    сцен. → Схема плана этих полей не содержит; xfade с перекрытием запрещён в v1.
11. **Стадия `edit` трогает деньги** через «перерендерить remotion-сцену с другим
    движением» — это $0 сегодня, но провайдер может смениться. → Перерендер
    только для провайдеров с `price_for == 0`; иначе `MotionOverride` → `block`
    с объяснением.
12. **Мок-паритет**: мок плана «всё cut» проходит линт и тесты, ничего не
    проверяя. → Мок обязан давать разнообразную форму (как мок планнера).
13. **Долгий вызов LLM** на 100+ сцен: полный план — ~7 минут, повтор удваивает.
    → «Только отклонения», при росте — резать по блокам сценария (тот же рычаг,
    что запланирован для планнера).
14. **Отчёт отстаёт от схемы**: новые поля есть, в HTML их нет, человек на воротах
    смотрит в JSON. → Монтажный лист — часть инкремента 2, не «потом».
15. **Vision-QA как истина**: 16 с на вызов, вердикт плавает. → Только совет на
    воротах; любой измеряемый дефект переводится в детерминированное правило
    рендерера или линта, а не в промпт QA.

**Ловушки, известные заранее.**
- Модель поставит переходы везде — квота в промпте плюс линт, не спорить с ней
  текстом. Перегруз после повтора → `failed`, а не третий заход.
- `emphasis` не из narration линт убирает молча: в промпте требование «verbatim».
- Ступени музыки относительно голоса: −9 громче, −30 почти тишина; модель может
  перепутать знак — линт зажимает в [−30, 0].
- `retention.json` есть только у эпизодов, прошедших режиссёра; у ручных
  раскадровок его нет — промпт это учитывает (`beats_text`), стадия не падает.
- Промпт длинный (rules + blueprint + библиотека приёмов), это дёшево: время
  зависит от ответа.
- Ни один новый провайдер, ни Remotion, ни Whisper не нужны.

**Не входит в этап 3:** несколько клипов на сцену (этап 4: варианты клипов
появятся, когда стадия `video` будет хранить прошедшие проверку попытки),
замер движения клипов (этап 5), SFX (этап 6), монтаж скачанного видео
(`clips_from_long`: ingest → transcribe локальным Whisper → highlights → сцены-
отрезки; схема отрезков плана к нему уже готова).
