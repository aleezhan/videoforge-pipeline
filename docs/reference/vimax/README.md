# Справка: агентные промпты из ViMax (HKUDS)

Отобранные файлы из [HKUDS/ViMax](https://github.com/HKUDS/ViMax) — «Agentic
Video Generation: Director, Screenwriter, Producer, Video Generator All-in-One»
(MIT — см. `LICENSE` рядом; снято 2026-08-28). Исследовательский проект
гонконгской лаборатории HKUDS: полный конвейер «идея → история → сценарий →
раскадровка → кадры → видео» на LangChain-агентах.

**Архитектура их нам не нужна** (LangChain, резидентные агенты, всё в памяти —
против наших принципов), но их промпты — это рабочая спецификация ровно тех
стадий, которые у нас на момент снятия справки были заглушками. Брать смысл, не
код: у нас промпты живут в `stages/prompts.py`, а структуры — в
`core/storyboard.py`.

> Уточнено 15.09.2026: заглушек больше нет. `director` — четыре шага с критиком
> и разметкой удержания (`stages/director.py`, `director_prompts.py`),
> `planner` — полноценная LLM-стадия с раскладкой времени, сверкой каста и
> стиля, проверками читаемости и однообразия (`stages/planner.py`). Пометки
> «(заглушка)» в таблице ниже оставлены как след: они говорят, чем мы были в
> августе, а не чем являемся. Невзятым из этой справки остаётся выбор лучшего
> кадра из N кандидатов (`best_image_selector.py`) — у нас цикл «сгенерил →
> проверил → перегенерил» с выбором лучшей попытки по журналу.

## Карта: какой файл к какой части videoforge

| Файл | Куда относится у нас | Главное |
|------|----------------------|---------|
| `screenwriter.py` | стадия `director` (заглушка) | Два промпта: «идея → история» (структура выхода: название, аудитория, синопсис 100–200 слов, персонажи, повествование) и «история → сценарий по сценам». Правила: сцена = единство времени и места; «show, don't tell»; всё описанное должно быть снимаемо («He clenched his fist», не «He was angry») |
| `storyboard_artist.py` | стадия `planner` (заглушка) | Промпт «сценарий сцены → раскадровка»: не больше одной реплики персонажа на кадр; позиция каждого элемента в кадре + направление взгляда; переиспользовать камеры (новая позиция камеры — только если ракурс существенно другой); каждый кадр описывается независимо, без ссылок на соседние. **Второй промпт — разложение кадра на первый кадр / последний кадр / движение** (first/last frame — чистые «снимки» без длящихся действий; в motion персонажа зовут по приметам, не по имени) + классификация величины изменения (large/medium/small). Это прямо под image-to-video и под провайдеров со start/end frame |
| `reference_image_selector.py` | стадия `images`, выбор референсов | LLM сам выбирает, какие референсы приложить к генерации кадра (макс. 8): портрет персонажа — только один ракурс, соответствующий направлению взгляда в кадре; уже одобренные кадры эпизода — как референсы окружения (приоритет — кадры той же камеры и более свежие); убирать дублирующие. Двухступенчато: при ≥8 кандидатов сначала дешёвый текстовый фильтр по подписям, потом мультимодальный. Наши подписи к референсам (`Reference`) — ровно то, что делает текстовый фильтр возможным |
| `best_image_selector.py` | стадия `images`, проверка | Альтернатива нашему циклу «сгенерил → проверил → перегенерил»: **сгенерировать N кандидатов и vision-LLM выбирает лучший** по референсам + описанию. Критерии: консистентность персонажа (пол, возраст, черты лица, телосложение, причёска), пространственная консистентность (кто слева/справа — как в референсе), соответствие описанию. Отбраковка кадров с рамками/полями |
| `character_portraits_generator.py` | портфолио (`gen-portfolio`) | Их ядро — всего 3 ракурса (фронт → бок и спина от фронтального), беднее нашего. Полезный трюк: портрет на широком 16:9 холсте с персонажем по центру и пустыми полями — чтобы модель не обрезала фигуру |

## Сквозные идеи

- **Кадр = первый кадр + последний кадр + движение.** Их центральная декомпозиция.
  Если когда-нибудь возьмём провайдера с поддержкой start+end frame (Kling,
  Hailuo), поле для этого в `Scene` уже подготовлено их схемой: `ff_desc`,
  `lf_desc`, `motion_desc`, `variation_type`.
- **Валидация выходов LLM с retry.** Каждый агент — pydantic-парсер + до 3
  ретраев; индексы, выданные LLM, проверяются на диапазон до использования
  (отрицательный индекс молча выберет не тот элемент). У нас так же — подтверждение.
- **Экономия на мультимодальных вызовах**: сначала текстовый фильтр по подписям,
  мультимодальный — только по короткому списку.

Чего не взяли: пайплайны целиком (`pipelines/*.py` — 50KB LangChain-оркестрации),
`global_information_planner`, `novel_compressor` (сжатие романов),
`camera_image_generator` — переклонировать при нужде.
