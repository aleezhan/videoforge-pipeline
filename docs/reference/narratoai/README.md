# Справка: промпты нарезок из NarratoAI

Отобранные файлы из [linyqh/NarratoAI](https://github.com/linyqh/NarratoAI) —
«одним кликом解说 и нарезка видео»: инструмент, который берёт длинное видео
(фильм, сериал, документалку), понимает сюжет по субтитрам, выбирает фрагменты
и пишет закадровый комментарий (MIT — см. `LICENSE` рядом; снято 2026-08-28).

Это ближайший работающий аналог нашего workflow `clips_from_long`. Промпты —
на китайском (проект китайский); при реализации переводить смысл, не текст.
Их конвейер: анализ сюжета → планирование сегментов → генерация текста
комментария → (у них дальше — сборка). Три файла ниже — эти три шага.

## Карта: какой файл к какой части videoforge

| Файл | Куда относится у нас | Главное |
|------|----------------------|---------|
| `plot_analysis.py` | `clips_from_long`, стадия анализа | Субтитры (с video_id и локальными таймкодами) → структурированный разбор: таблица персонажей с **пометкой достоверности** («в субтитрах явно / из поиска / разумный вывод»), сюжет 120–220 знаков, посегментная таблица с таймкодами и нарративной функцией, кандидаты на «оставить оригинальный звук». Жёсткое правило источника истины: субтитры > интернет-поиск; то, чего в субтитрах не было, — только в раздел «не покрыто, осторожно» |
| `segment_planning.py` | `clips_from_long`, стадия планирования | Выбор фрагментов до написания текста. Ключевые правила: сначала причинная цепочка «положение героя → событие → изменение → новый кризис → саспенс», потом выбор; флаг **OST** на сегмент (1 = оригинальный звук для ключевых реплик, 0 = будет закадровый текст); не больше 2 OST=1 подряд; оригинальный звук — 3–10 секунд; мост-сегмент при переходе между видео; каждый сегмент несёт явную нарративную функцию (`story_role`, `intent`, `transition`); интро/титры/реклама выбрасываются безусловно; **«знаки комментария / 5 = нужные секунды видео»** — плотность текста подгоняется под длину фрагмента |
| `script_generation.py` | `clips_from_long`, стадия текста | Написание комментария поверх готового плана. Главный приём — **жёсткая привязка**: LLM может заполнить только `picture` и `narration`, а `_id`, `video_id`, таймкоды и OST обязан скопировать из плана байт-в-байт (наша философия «контракт + стадия заполняет свои поля»). Каждый закадровый кусок — «мост»: что случилось до, почему герой так делает, что нового; формула открывающего хука «положение героя + аномалия + вопрос»; таймкоды локальные для своего файла, не сквозные |

## Сквозные идеи

- **План отдельно, текст отдельно.** Выбор фрагментов и написание комментария —
  разные LLM-вызовы с разными правилами, и второй не имеет права менять решения
  первого. Ложится на наш конвейер один в один: две стадии, между ними —
  раскадровка с `Scene.source` (поле уже заложено).
- **Бюджет длительности текста.** Знаки/5 = секунды — простая формула, которая
  спасает от «80 знаков на 6-секундный фрагмент». У arcads-справки есть
  зеркальная таблица для генерации видео (слова сценария → секунды клипа).
- **Достоверность как поле.** Всё, что LLM «понял», размечается: из субтитров /
  из внешнего источника / вывод. Дешёвая защита от галлюцинаций в анализе.

Чего не взяли: пакеты `documentary` (документалки с покадровым анализом),
`short_drama_narration`/`short_drama_editing` (вертикальные мини-дорамы — те же
идеи, другие константы), `script_matching`/`script_repair` (сшивка и починка
JSON), код сборки (MoviePy). Переклонировать при нужде.
